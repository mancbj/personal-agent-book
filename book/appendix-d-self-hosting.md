# 附录 D · 自托管入门路径

自托管适合你需要本机应用、私有网络、严格数据边界，或愿意管理自己的工作环境时。它给你更多配置选择，也需要有人负责更新、备份和故障。若主要需求是跨设备随时联系，又不愿维护主机，可以先试托管服务，或者只把必须的部分留在本地。

本附录提供起步与验收路径，不把安装成功当成任务已经可靠。**文档核查日期：2026-10-10；本书未在各平台执行安装实测。** 安装与配置命令留给读者在自己选择的环境执行，实际依赖和选项以当时官方文档为准。

## 第一步：决定哪一部分要自己管理

| 路径 | 适用条件 | 要承担的工作 |
| --- | --- | --- |
| 本机运行 | 本机文件、应用、硬件或网络不可直接交给纯云端执行 | 开机与休眠、账号、工具权限、备份 |
| 自托管服务器 | 需要持续在线，并可将所需资源放在该环境 | 主机费用、更新、访问控制和恢复 |
| 托管开放运行时 | 想使用相关生态，但不想自己部署主机 | 核对服务边界、版本、计费与资料导出 |
| 本地与云端混合 | 必须接触本地资源，也需要远程服务 | 划分执行、推理、状态与数据流 |

再单独选择模型在哪里运行。使用云模型，需要合法有效的服务账号和费用安排；全本地模型需要兼容性、容量与任务表现达标。没有统一适用于所有人的硬件配置。先用目标任务试验，再决定购买设备。

## 第二步：准备一个能停、能恢复的小环境

准备一份测试目录、非敏感样本与明确输出目录。把原文件留在测试范围之外，先避免对外发送、付款和不可逆删除。明确谁维护环境，以及资料、配置、日志和凭证分别在哪里。

检查网络能否访问需要的官方安装源与模型服务，组织是否允许安装和连接相应资源。不要为了得到一个常驻入口，就把没有鉴权的控制面板直接暴露到公网；远程访问按项目的鉴权和网络文档配置。

这些是起步任务的约束，不表示仅换个系统账号或测试目录就完成了安全隔离。工具的实际执行权限、挂载与网络仍需验证。

## 第三步：从官方路径安装一种运行时

先选择一种，不必同时安装多套环境。这里保留官方文档入口和少量起步命令，避免把快速变化的安装脚本复制成第二份维护对象。

### OpenClaw

截至核查日，[安装文档](https://docs.openclaw.ai/install)与[快速开始](https://docs.openclaw.ai/start/getting-started)列出 **Node.js 24.16+ 或 26.1+，推荐 Node 26**，并有 macOS、Linux、Windows 的入口。旧资料中的 Node 22 要求不能直接套到当前文档。

桌面用户可按文档选择 macOS 应用或 Windows Hub；命令行用户采用对应系统的官方安装入口。阅读安装方式会下载和修改什么，再执行适合你的路径。不要把来源不明的转载命令当成官方版本。

安装后，按引导选择模型访问与必要连接。当前快速开始说明可以用 `openclaw configure` 返回设置；`openclaw gateway status` 检查网关状态，`openclaw dashboard` 打开界面。先确认一次真实对话成功，再考虑按文档用 `openclaw gateway install` 安装后台服务。

后台服务不能阻止笔记本休眠，也不能让已经断开的业务登录继续有效。本地模型路径见[自定义服务与本地运行说明](https://docs.openclaw.ai/concepts/model-providers/custom-providers)。隔离设置按[信任边界](https://docs.openclaw.ai/start/why-openclaw/the-trust-boundary)确认，不由“已安装”推断。

### Hermes

截至核查日，[安装文档](https://hermes-agent.nousresearch.com/docs/getting-started/installation/)说明第一方安装使用受管理的 **Python 3.14**，不能把兼容范围误读成当前全部旧版 Python 都受支持。完整桌面包与从源码构建的安装器有不同依赖路径；macOS 当前说明限 Apple Silicon，其他系统按对应入口选择。

安装后，`hermes setup` 进入设置，`hermes model` 选择供应方与模型，`hermes` 开始对话。已有付费服务是否能用于此配置，按供应方准入与计费条件检查；自带密钥、Portal 或本地服务是不同路径。

当前快速开始提供 Blank Slate 最小设置，但其中仍有基础文件与终端能力，不能理解成绝对无权限。先确认实际工具列表与执行范围，再按需要启用其他能力。诊断可用 `hermes doctor`；确需消息入口与常驻工作，再依据[快速开始](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart/)配置 `hermes gateway setup`。

如果选择本地模型服务，核对端点、模型名称与任务表现；自定义端点不是“完全离线”的充分证据。

## 第四步：验收三项小任务

安装过程中选择的功能，与任务里真正生效的功能可能不同。用下面三个低风险任务检查，不成功时先排查该层，不急着扩大权限。

| 小任务 | 怎样准备 | 成功标准 |
| --- | --- | --- |
| 一次真实对话 | 仅启用一个已配置模型，不添加复杂路由 | 能回答，供应方与模型符合预期，费用入口可查看 |
| 读取与草稿 | 提供三份测试文件，要求摘要与来源文件名 | 引用正确，输出写到指定测试位置，没有修改原文件 |
| 等待与恢复 | 人工设置一个安全停点，再确认继续 | 能说清状态，恢复后不重复已经完成的动作 |

读者若以“不外发”为目标，还要验证模型、工具、日志与更新组件的网络行为。一般任务试跑不能证明绝对零外发；需要相应配置检查和适合的网络观察。

需要离线工作时，在依赖准备齐全后断网，执行一项只依赖本地资料的任务。记录哪些部分可继续、哪些依赖远端而停止，不能拿一个离线摘要证明所有业务都可离线。

## 第五步：只在验收后安排长期运行

明确任务的拥有者、触发时间与时区、输入范围、预算、完成标准和异常停点。先手动运行一次，再安排重复。消息平台的机器人能收到消息，不表示所有来访者都应该获得相同工具权限。

常驻环境要能被检查：进程是否在运行，最近一次任务结果是什么，错误由谁处理。根据任务需要检查休眠、电源、磁盘空间、网络与登录期限；没有任务要求时，不必为了“全天候”增加服务器。

费用至少记两栏：设备、电力、托管、模型和第三方工具是一栏；安装、监督、排错、更新和恢复时间是另一栏。两栏与附录 C 的任务收益一起看。

## 第六步：让更新和退出有路径

第一次升级前，记录当前发行版、模型配置与工具列表，保存必要配置、任务状态和测试结果，确认备份包含什么以及怎样恢复。对正在行动的任务先暂停，并核对外部消息或订单的实际状态。

使用所选安装方式对应的更新机制，不混用包管理器、桌面更新器与源码路径。升级后重跑前面的三项小任务。回退软件并不会撤回已经发送的消息或业务订单；外部动作另行处理。

退出时依次停用任务与触发器、停止服务、撤销不再使用的访问，再决定保留或删除哪些资料。卸载程序可能不会删除状态，也不会自动撤销远端令牌，需按相应项目与服务说明确认。

## 遇到问题，先判断是哪一层

| 现象 | 优先检查 | 不要急着做的事 |
| --- | --- | --- |
| 安装完成但没有回答 | 模型登录、端点、网络、额度与诊断信息 | 同时添加多个模型和路由 |
| 回答正常但读不到文件 | 路径、账号、工具配置与挂载范围 | 给整个主目录或整台机器放开权限 |
| 常驻任务未启动 | 进程、休眠、触发器、时区与拥有者 | 认定更贵模型一定能修复 |
| 重试产生重复结果 | 原动作是否已经完成，业务是否支持安全重试 | 未核对状态就再次提交 |
| 更换模型后效果变差 | 工具调用、格式遵循与同任务验收 | 只按模型宣传排名判断 |

想继续深入时，以 [OpenClaw 官方文档](https://docs.openclaw.ai/)和 [Hermes 官方文档](https://hermes-agent.nousresearch.com/docs/)为入口，阅读当前安装、模型、工具、权限、备份与升级说明。本书负责帮助你建立判断路径，不把一个固定安装命令承诺成永久可用方案。
