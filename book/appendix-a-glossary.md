# 附录 A · 术语速查

这份词表沿用正文的用法，帮助你阅读产品资料和填写后面的工作表。行业中的名称仍在变化；名称相同，不代表能力、运行位置或授权相同。

## 从目标到执行

| 术语 | 本书中的意思 | 读产品资料时继续问 |
| --- | --- | --- |
| 个人智能体（Personal Agent） | 围绕个人的持续关系，在授权范围内保留必要上下文、行动和跟进 | 接手哪件事？离开后怎样继续？ |
| AI 助手（AI Assistant） | 广义协助入口，可能以回答为主，也可能具有行动能力 | 能准备建议，还是能实际执行？ |
| 任务代理（Task Agent） | 围绕一项明确目标组织步骤和工具 | 任务结束的标准是什么？ |
| 工作代理（Work Agent） | 面向专业工作、组织资源和交付流程的代理 | 谁验收？谁能批准？ |
| 企业流程智能体 | 由组织指定，在限定业务流程与权限中推进任务 | 代表哪个团队？谁负责异常和撤销？ |
| 大语言模型（LLM） | 理解、生成与选择行动所用的模型组件 | 具体型号和供应方是什么？ |
| 工具（Tool） | 查询、读取、修改或执行某项动作的接口 | 实际能接触什么，能改什么？ |
| 函数调用（Function Calling） | 模型生成结构化工具请求的一种机制 | 请求是否执行，结果是否检查？ |
| 连接器（Connector） | 把邮箱、日历、文件等资源接入工作环境的组件 | 支持哪些对象和读写操作？ |
| 运行时（Runtime） | 管理任务执行、工具调用、状态和运行条件的软件环境 | 进程在哪里，由谁维护？ |
| 网关（Gateway） | 按具体项目设计连接消息入口、会话或运行服务的组件 | 网关在哪台主机，怎样鉴权？ |
| 电脑操作（Computer Use） | 通过界面观察与输入操作应用的能力 | 登录、验证码和重要动作由谁处理？ |
| 行动循环（Agent Loop） | 根据目标选择动作、执行、观察，再调整下一步 | 卡住时怎样识别和交回？ |

## 跨时间工作

| 术语 | 本书中的意思 | 容易混淆的区别 |
| --- | --- | --- |
| 上下文（Context） | 当前任务可用的指令、资料与相关信息 | 不等于永久记忆或全部历史 |
| 记忆（Memory） | 为后续工作保存的事实、偏好或方法 | 记得偏好，不等于获得行动许可 |
| 任务状态（Task State） | 已完成什么、正在等什么、下一步由谁负责 | 聊天记录不一定包含可恢复状态 |
| 技能（Skill） | 可复用的方法、步骤或知识，各项目定义不同 | 保存方法，不等于安排了触发时间 |
| 例行／定时任务（Routine／Scheduled Task） | 按时间或事件触发的委托 | 触发成功，不等于结果已验收 |
| 主动工作（Proactive Work） | 在变化或持续规则下发现并推进需要关注的事项 | 各产品后台读写边界不同 |
| 常驻（Persistent／Always-on） | 入口或运行环境能持续存在 | 服务器开着，不等于任务仍在推进 |
| 多代理（Multi-agent） | 多个角色或执行单元协作 | 角色不同，不等于资源和凭证隔离 |
| 检查点（Checkpoint） | 可用于核对或恢复的阶段记录，具体形式随系统而异 | 有摘要，不等于能恢复外部业务状态 |
| 幂等（Idempotency） | 重复请求不会重复产生同一项业务效果的性质 | 自动重试未必具备这一性质 |

## 运行位置与控制

| 术语 | 本书中的意思 | 要确认的条件 |
| --- | --- | --- |
| 本地部署（Local Runtime） | 代理运行与一部分执行位于用户本机或受控本地环境 | 模型、工具与日志是否也在本地？ |
| 云端派（Managed Cloud Agent） | 厂商托管的持续代理服务，本书用来与本地派并列讨论 | 地区、账号、数据处理和费用 |
| 自托管（Self-hosting） | 用户或其团队负责运行环境的部署与维护 | 可以在本机，也可以在云服务器 |
| 混合部署（Hybrid Deployment） | 本地与远程组件共同完成任务 | 逐项写明执行、推理与资料流向 |
| 设备端推理（On-device Inference） | 模型计算在指定实体设备上完成 | 整个任务、工具和日志是否仍使用云端？ |
| 本地推理（Local Inference） | 模型计算在可用的本地环境完成 | 其他搜索、工具、日志仍可能外发 |
| 开源（Open Source） | 相应代码依许可证开放查看、修改和使用 | 不自动保证零成本、隔离或可迁移 |
| 沙箱（Sandbox） | 对进程访问文件、网络或系统能力设置边界的环境 | 是否启用，哪些挂载和网络仍可用？ |
| 凭证（Credential） | 访问账号或服务所用的密码、令牌等 | 谁能读取，怎样撤销和更换？ |
| 最小权限（Least Privilege） | 只授予完成当前任务必要的访问和行动范围 | 能否按目录、对象、渠道和期限缩小？ |
| 提示注入（Prompt Injection） | 输入或外部资料试图改变模型行为、绕过原指令 | 外部内容是否被当成授权？ |

## 协议、授权与判断

| 术语 | 本书中的意思 | 不应据此推出 |
| --- | --- | --- |
| MCP（Model Context Protocol） | 连接模型应用与工具、资源的一套协议；正文引用特定版本 | 所有工具安全、结果正确或状态互通 |
| A2A（Agent2Agent） | 面向代理间交互的协议方向；本书仅作为相关机制提及 | 所有个人智能体已经实现统一协作 |
| AP2（Agent Payments Protocol） | 围绕代理支付与用户授权证据的协议方向 | 普遍商家覆盖或统一法律责任已经实现 |
| 一次授权（One-time Approval） | 为明确的一项动作或范围作出许可 | 自动扩展成长期授权 |
| 常设授权（Standing Authorization） | 在明确对象、动作、期限和例外内可重复使用的许可 | 代理可自行扩大额度或范围 |
| 人机交接（Human Handoff） | 把登录、确认、异常或判断交还给人 | 所有交接都算失败 |
| 净时间收益（Net Time Saved） | 可比手工主动时间减去使用代理后的全部主动投入 | 用运行时长直接当作人节省的时间 |
| 物理停点 | 设备或机器人在越界、故障或不确定时停止新动作并交回控制 | 语言模型说“停止”不等于执行器已有安全停机机制 |
| 可迁移性（Portability） | 能带走必要资料并在另一环境恢复需要的工作 | 只下载聊天记录就算迁移完成 |
| 法律人格（Legal Personality） | 法律承认的权利义务主体资格 | 邮箱、电话、钱包或品牌名称自动赋予资格 |

这些解释是便于阅读的工作定义，不是替代协议规范或法律定义。技术出处主要见 [MCP 工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)、[OpenClaw 文档](https://docs.openclaw.ai/)、[Hermes 文档](https://hermes-agent.nousresearch.com/docs/)及 [OWASP 提示注入说明](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)。企业授权、设备行动与迁移范围详见第 9—11、14 章。
