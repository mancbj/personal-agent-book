# 第三篇来源记录与历史口径

核查日期：**2026-10-10**。对应版本：**v0.3.0-part3**，前三篇合刊，第 1—10 章。作者明确要求“继续写第三篇”；本次新增第三篇阅读说明、第 10 章及一张演进图，未开始第四篇和附录。

历史章节只保留解释当下所需的节点。日期按愿景、研究、能力发布、产品公布或开放分别说明，不设整个个人智能体品类的唯一诞生日。旧资料支持当时的事件与阶段，不说明产品今天仍处于相同状态。

## 访问限制与未采用的说法

- ACM 原始页面与另一个 CACM 页面抓取受限，原论文存档 PDF 也未完整读取。MIT 原始研究组目录与论文检索摘要支持本章有限描述；没有写成已阅读全文。
- Android 2012 年 6 月的月归档读取失败，采用已成功读取的开发者发布记录和 2013 年官方回顾；没有把未读归档作为唯一依据。
- Echo 原始 2014 年公告未在本次检索中定位到可读版本，采用 Amazon 2015 年公告中的明确回顾，区分首发、销售扩展与发货。
- M 的真人参与有原始采访与官方回顾支持，但本章不新增关停时间、内部财务或技术失败的因果结论。
- 附件中有关 OpenClaw、Hermes 在特定月份首发、所有主流产品必然采用相同架构等说法，未充分独立核实，不填入时间图。
- 第一、二篇的当下产品事实未在本章改写成历史先后排名；没有新增套餐、地区、融资与用户量比较。

## 输入素材中的矛盾怎样保留

| 不同解释 | 本章处理 |
| --- | --- |
| 1987 愿景、1994 研究、2011 移动入口、近期常驻产品，各被用作起点 | 分成四个问题，区分事件类型；都不宣布为整个类别的唯一诞生日 |
| 博主按四代介绍能力与运行环境，部分研究更强调持续性或云电脑 | 将四代保留为一种体验分类，同时用早期云语音服务、当下云端托管开放运行时等反例，说明不能充当统一历史阶梯 |
| 云端为本地之后的升级，或本地为巨头产品之后的反击 | 不为部署方式设置胜负顺序。本地资源、受控环境与托管服务按条件并行，混合方案单独说明 |
| M 的结果显示强大代办能力，或被用于证明机器曾经全面失败 | 结果与执行者分开。真人参与不能证明机器独立能力，也不能据有限事实还原内部经营原因 |
| 新论文、协议或能力发布就是新品类诞生 | 方法、接口、协议、运行环境与产品分别说明；组件汇合是作者分析，未虚构单一路线或直接继承关系 |
